# 口径原则（Caliber Principles）

> 面向对象：任何要改动 `backend/app/metrics.py`、`server.py` 或页面数字的人。
> 这里只写**原则本身**：每条是什么、为什么、怎么算违约。
> 具体操作流程见 `.agents/skills/add-metric/`，接口能力见 `DATA-MAPPING.md`。

这六条是这个看板能被信任的前提。它们不是风格偏好 —— 每一条都对应一类真实发生过的错误。

---

## M1｜先求和再相除

**规则**：比率型指标（AI 代码占比、补全采纳率）必须由**聚合后的分子 ÷ 聚合后的分母**得出。

**为什么**：各部门产出量差异可达 10 倍。对个人比率取算术平均，会让一个只写了 50 行的
新人的 100% 占比，和写了 2 万行的骨干的 80% 占比等权，得出扭曲的部门结论（辛普森悖论）。

**怎么算违约**：
```python
# ✗ 违约：对个人比率求平均
dept_rate = sum(m.code_generate_rate for m in members) / len(members)

# ✓ 合规：先求和再相除
dept_rate = sum(m.ai_lines for m in members) / sum(m.total_lines for m in members) * 100
```

**验证**：`server.py --selftest` 的比率校验；也可手工比对
`org.codeGenerateRateByLines` 与 `org.aiCodeLines / org.totalNewCodeLines`。

---

## M2｜部门 = 成员之和

**规则**：部门级与公司级指标一律由成员日粒度求和得出，不单独计算。

**为什么**：一旦部门口径独立实现，它和成员明细就会漂移，业务方点开下钻会发现
「部门说 32 万行，成员加起来 29 万行」，整个看板的可信度归零。

**怎么算违约**：部门值不是成员值的和（误差 > 0.01）。

**验证**：`--selftest` 末尾强制校验三行相等：
```
部门汇总 credits == 成员汇总 credits == 公司总量 credits
```

**注意**：本条针对**数值口径**。数据获取路径可以变（消耗维度可直接按部门查
`usage/members/detail`），但进入看板前仍要满足这条不变量。

---

## M3｜消耗与产出成对出现

**规则**：任何展示 AI 代码占比的位置，都必须同时能看到 Credits 消耗与绝对产出量。

**为什么**：占比是**比率**，单独看会得出「占比 95% = 提效」的错误结论 ——
实际可能只是产出极少（3 行里 3 行是 AI 写的）。必须让人一眼看到分母有多大。

**怎么算违约**：页面/表格/卡片只给占比，同视图内无法看到消耗或绝对行数。

**落地要求**：KPI、图表、表格三类视图都要满足；`MetricsPage` 的指标字典里每条占比
指标都必须写明「与谁配对看」。

---

## M4｜环比区间等长

**规则**：对照周期与当前窗口**严格等长且紧邻**。

**为什么**：近 30 天对「上月」或「年初至今」会让增长率失去意义（2 月对 1 月天然下滑）。

**怎么算违约**：`previousRange()` 返回的区间长度 ≠ 当前区间长度，或两者不相邻。

**落地要求**：筛选条上必须**显式展示**环比对照区间 —— 这是最容易被追问的点
（"你这个 +12% 是和什么比？"）。

---

## M5｜查询失败不得降级为 0

**规则**：接口失败要显式报错或在页面上标注「指标不可用」，不得用 0 代替。

**为什么**：这个看板的用途包含**余额预警**。把「查询失败」渲染成「额度用尽」
会触发误充值；把「APM 不可用」渲染成「失败率 0」会掩盖真实故障。两者都比报错更糟。

**怎么算违约**：
```python
# ✗ 违约
try:
    data = fetch_metrics()
except Exception:
    data = {"error_rate": 0}

# ✓ 合规
except Exception as exc:
    return err(50000, f"指标查询失败：{exc}")   # 或前端渲染空态 + 原因
```

**落地要求**：`null` 与 `0` 在类型上必须可区分（`number | null`），前端分别渲染为
「—」与「0」。私有化未配 APM 时可观测域返回 404 属**预期降级**，不是错误。

---

## M6｜额度风险按额度周期算

**规则**：额度使用率 = 消耗 ÷ 周期限量，分子必须是**额度周期内**的消耗。

**为什么**：看板窗口（近 30 天）与额度周期（自然月 / 订阅生效日切片）通常不对齐。
用 30 天窗口去除以月度限量，会得出「只用了 60%」的假安全结论，实际周期已用满。

**怎么算违约**：额度页使用 `range` 而非 `quotaCycle` 作为统计区间。

**落地要求**：额度页默认「对齐额度周期」，并保留切换到看板窗口的开关；
周期切分以 `cycleMode` 为准（`cycleType` 只是档位标签，不决定切分口径）。
